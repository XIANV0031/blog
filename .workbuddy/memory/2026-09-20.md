### 本轮踩的六个坑（均已沉淀进 skill 第 4.9 节）

1. **`<img` 与属性之间的换行被 `--minify` 吃掉 → 产出 `<imgsrc=...>`**
   最阴的一个：标签名成了 `imgsrc`，**图片完全不会加载**，CSS/JS 全查不到，
   无任何报错，构建显示成功。表现是「产物里有 figure，浏览器里没图」。
   解法：照抄主题写法，属性 merge 成 dict 后逐条 `printf`，全跟在 `<img` 同一逻辑流。
   兜底检查：`grep -c 'imgsrc' public/posts/*/index.html` 必须为 0。

2. **`<figure>` 被 Goldmark 包进 `<p>`（非法嵌套）**
   浏览器会提前闭合 `<p>` 并把 figure 提到外面，DOM 与源码不一致。
   解法：`wrapStandAloneImageWithinParagraph = false`。

3. **图片属性块 `{class="..."}` 必须独占一行**
   写在图片同行（`![...](...){class=...}`）会被 Goldmark **静默忽略**。
   Hugo 最小复现测出：独占一行才生效。另需开启
   `[markup.goldmark.parser.attribute] block = true`。

4. **CSS 特异性陷阱：特例规则被主规则静默覆盖**
   主规则 `.post-content img:not(...)×4` 特异性 (0,1,4)；
   特例 `.post-content img.wide-banner` 只有 (0,2,1) → 样式不生效且不报错。
   解法：特例规则**照抄完整排除链**再加 class。
   同类问题：`@media` 里的窄屏规则漏写 `:not()` 会让 TOC 图标被套上裁切。

5. **`merge .Attributes` 里没有 `class` 时不会报错**（与坑 3 同源）

6. **本地验证必须用 `public-preview`**
   `public/` 按线上 baseURL（含 `/blog/`）构建，本地服务器根目录下没有 `/blog`
   → 全部 404。须另行 `--baseURL 'http://127.0.0.1:8098/'` 构建预览产物。

### 三条硬约束（做之前必须先确认）

1. **`body::before` / `body::after` 已被占用** —— 分别是 CRT 扫描线（z=9999）
   与顶部沙色条纹（z=10000）。动态背景**只能另起独立 DOM 元素**（`.tac-bg`，z=0，
   挂在 body 首子元素）。
2. **绝不能写 `prefers-reduced-motion: reduce { * { animation-duration: 0.01ms } }`**
   —— 一刀切会让开启「Windows 辅助功能→动画效果=关闭」的机器**整站动画全灭**
   （用户在 v1 实际遭遇过）。现行策略是**分级响应**：装饰性动效不受 reduce 影响，
   只对"跟随鼠标的持续位移"降级。
3. **禁止铺屏多边形装饰** —— 手机上占比超 100% 会糊满屏盖住正文
   （v2 的历史教训，用户原话「背景这堆多边形是什么鬼，删了」）。

### 本轮踩的五个坑（均已沉淀进 skill 第 4.10 节）

1. **⭐ 改了 CSS 却忘了重建产物 → 误判"选择器没生效"**
   改完 21.9 节跑验证，报 `main: auto/relative`（预期 `10/relative`），
   反复怀疑选择器写法、主题类名、CSS 特异性，查了半天。
   真相是 `public-preview/` 还是改动**之前**构建的产物（产物 489 行 vs 源码 522 行）。
   ⚠️ **`hugo --minify` 不压缩 `static/` 下的 CSS/JS**（原样复制），
   所以无法从产物大小判断新旧，**必须比 `wc -l` 或 mtime**。
   → 铁律：任何 CSS/JS 改动后，**先重建产物再验证**。

2. **图片「先小后大」的循环依赖陷阱**
   天真写法：figure 满宽 + `img { width: 62% }`。**这会坏** —— img 的 62% 是相对
   figure 算的，而 figure 保持 100%，figure 不会因内部 img 变窄而变窄，
   figcaption 作为 figure 直接子元素自然也是满宽。
   实测：**图内容 533px（62%）、图注 860px（满宽）** —— 「小图 + 一条超长的图注」。
   → 正解：**让 figure 本身收窄**（CSS 变量 `--fig-w` 做单一事实来源），
   img 在 figure 内填满（`width: 100%`）。
   验证标准：**`figure` / `img` / `figcaption` 三者宽度必须完全相等**。

3. **主题原有的 `img:hover { scale(1.025) }` 与新宽度放大叠加 → 溢出**
   `tactical-motion.css` 第 779 行有这个规则。叠加后：
   `figure 791px × 1.025 = 810.97px`、`wide 860px × 1.025 = 881.5px`
   —— **超出 860px 版心，压到右边距**。
   → 在 figure 内显式 `transform: none !important` 归零。
   ⚠️ 验证时不能只看 `width`（不含 transform），要用 `getBoundingClientRect().width`。

4. **窄屏回退不能只写 `@media (hover: none)`**
   `:hover` 无关断点只覆盖**触屏设备**。桌面浏览器把窗口拖窄到 600px 时
   仍是 `hover: hover`，此时 62% 只有 ~372px，图小得看不清（实测确认）。
   → 必须**另补一条 `@media (max-width: 900px)`** 放宽到 100%，与触屏条件**并列**。

5. **headless 下 `:hover` 不生效**
   用 CDP `Input.dispatchMouseEvent` 移动鼠标后 hover 样式**不触发**，
   两次测量结果完全一致，看起来像"测不出效果"。
   → 必须开 `Emulation.setFocusEmulationEnabled({ enabled: true })`。
   另：`scrollIntoView` 会改变坐标，必须**先滚动、等稳定、再取坐标**，
   否则用旧坐标鼠标打偏。

### 技术要点

- **双层 lerp 做视差**：外层光晕慢（`LERP_SLOW = 0.075`）、内核快（`LERP_FAST = 0.28`）。
- **rAF 收敛判定**：连续 12 帧位移 <0.35px 才停循环
  （⚠️ 不能一帧就停，会留极小残差看着像"没跟到位"）。
- **`mix-blend-mode: screen` 必须放在正文之下**（z=1/2）——
  放在正文之上会让文字被逐帧加亮，构成阅读干扰。
  同时给 `.main / .post-single / .list` 设 `position: relative; z-index: 10`，
  ⚠️ **但不能加背景色**（会盖住 z=0 的动态背景层）。
- **`conic-gradient` 扫掠是最贵的元素**（210vmax），窄屏降透明度、小屏直接隐藏。
- CDP hover 测试脚本：`.cache/tools/figcheck.mjs`；层级 `.cache/tools/zcheck.mjs`；
  性能 `.cache/tools/perf-check.mjs`；回退矩阵 `.cache/tools/resp-check.mjs`。
